## 개념 정리

### 관계형 데이터 처리 흐름
![[ods_dw_dm_data_pipeline_layers.png]]

- ODS (**O**perational **D**ata **S**tore)
	- 운영 시스템의 데이터를 거의 원본 형태로 한곳에 모아두는 중간 저장소
	- "지금 이 고객의 최신 주소는?" 같은 현재 상태 조회를 담당
	- 코드값 통일, 타입 정리, 중복 제거 같은 기본 정제를 ODS에서 진행
	- 단, 조직마다 의미와 범위가 다를 수 있음

- Data Warehouse (DW)
	- 전사 데이터를 주제 영역별(고객, 주문, 상품)로 통합해 장기 이력을 쌓아두는 곳
	- 대표 기술/제품 : Snowflake, BigQuery, Redshift

- Data Mart (DM)
	- DW의 부분집합을 특정 부서나 용도에 맞게 잘라서 미리 집계해둔 것입
	- 영업 마트, 재무 마트처럼 나누고, 비정규화와 사전 집계로 조회 속도를 올림


⭐️ 이 개념들을 관계형 데이터를 전제로 만들어진 개념이라, 비정형 데이터에는 그대로 대응시키기는 어려움


### Data Lake
- 다양한 출처의 정형/반정형/비정형 데이터를 가공하지 않은 원시 상태(Raw data) 그대로 저장하는 중앙 집중식 통합 저장소
- 대표 기술/제품 : AWS S3, GCS, Azure Blob, Hadoop


### Data Lakehouse
- Data Lake의 저렴하고 유연한 대용량 저장 능력과 Data Warehouse의 빠르고 체계적인 분석 관리 기능을 하나로 결합한 최신 데이터 아키텍쳐
- 한마디로 레이크에 저장된 데이터 위에 웨어하우스 기능을 올려서 한 곳에서 분석/관리까지 끝내는 아키텍쳐
- Medallion 구조 : 데이터를 단계별로 정제하는 구조
	- Bronze : Raw data를 저장
	- Silver : 결측치 처리, 스키마 검증, 비즈니스 규칙 적용을 거친 정제된 데이터
	- Gold : 특정 부서나 분석·보고서 용으로 join 및 요약 집계된 최종 데이터 (기존의 Data Mart 역할)
- 대표 기술/제품 : Databricks, Iceberg/Delta 기반 레이크하우스

### Data Fabric
- 분산되어 있는 여러 데이터 소스를 물리적으로 한 곳에 모으지 않고도 ==메타데이터==를 기반으로 통합된 하나의 데이터 계층처럼 접근/관리할 수 있게 한 설계 방식
- 주요 구성 요소
	- 데이터 카탈로그 및 메타데이터 수집 계층
	- 지식 그래프 (데이터 간 의미적 관계 표현)
	- 데이터 통합 계층 — ETL/ELT, 스트리밍, 데이터 가상화를 상황에 맞게 혼용
	- 거버넌스·보안 (계보 추적, 접근 제어, 마스킹)
	- 오케스트레이션 및 추천 엔진
