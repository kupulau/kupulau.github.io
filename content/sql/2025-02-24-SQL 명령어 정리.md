### SELECT
```
SELECT column1, column2 FROM table_name;
```
`table_name`에서 `column1`, `column2` 열의 데이터를 조회한다. 전체 열을 조회하고 싶다면 `SELECT * FROM table_name;`를 하면 된다.

#### 조건 추가 (WHERE)
```
SELECT column1, column2 FROM table_name WHERE column1 > 500;
```
`column1`의 값이 500 초과인 `table_name`의 `column1`, `column2` 데이터를 조회한다.

#### 정렬 (ORDER BY)
```
SELECT column1, column2 FROM table_name ORDER BY column2 DESC;
```
`column2`의 값을 내림차순(DESC)으로 정렬한 `table_name`의 `column1`, `column2` 데이터를 조회한다. 오름차순으로 정렬하는 것은 `ASC`를 사용하면 된다.


#### GROUP BY
```
SELECT column1, SUM(column2) as column3 FROM tbl GROUP BY column1;
```
GROUP BY는 같은 값을 가진 행들을 하나의 그룹으로 묶어서 집계 연산을 수행할 때 사용하는 옵션이다. 

예를 들어 아래와 같이 부서 번호에 따른 월급 정보 데이터를 담은 `tbl`이 있다고 하자.

|Dept_no|Salary|
|:--:|:--:|
|20|800|
|30|1600|
|10|2450|
|30|1250
|10|5000|
|20|2975|

여기에서 아래 명령어를 이용하면 부서를 그룹끼리 묶어서 그 부서에서의 월급 합계를 조회할 수 있다.

```
SELECT Dept_no, SUM(Salary) as Total_salary FROM tbl GROUP BY Dept_no;
```

|Dept_no|Total_salary|
|:--:|:--:|
|20|3775|
|30|2850|
|10|7450|

이외에도 `COUNT`, `AVG`, `MAX`, `MIN` 등의 집계 함수와 자주 쓰인다. 

#### HAVING
HAVING은 GROUP BY 연산이 끝난 결과에 대해 HAVING 절의 조건을 만족하는 그룹만 추출하는 옵션이다.
```
SELECT column1 FROM tbl GROUP BY column1 HAVING 조건
```

예를 들어 이런 `tbl`이 있다고 해보자.

| |id|
|:--:|:--:|
|1|100|
|2|100|
|3|200|
|4|200|
|5|200|
|6|999|
|7|999|

여기에 아래와 같이 HAVING을 이용하면 id가 같은 것끼리 grouping을 하되 2개씩 grouping된 것들만 반환된다. (id=200인 행이 3개이므로 HAVING 절의 조건을 충족시키지 않아서 반환되지 않았다.)

```
SELECT id FROM tbl GROUP BY id HAVING COUNT(*) = 2;
```

|     | id  |
| --- | --- |
| 1   | 100 |
| 2   | 999 |


#### alias 사용
테이블에 별칭(alias)을 붙여 조회할 수도 있다.
```
SELECT A.name, B.age FROM tbl1 A, tbl2 B WHERE A.name = B.age;
```
`tbl1`을 `A`, `tbl2`를 `B`라고 별칭을 붙인 후, `tbl1`의 `name`과 `tbl2`의 `age`가 동일한 행을 추려서 그 `name`과 `age` 데이터를 조회한다.
이 때 실행 순서는 `FROM` → `WHERE` → `SELECT` 순이다.

테이블 뿐만 아니라 열의 이름도 alias를 사용할 수 있다.
```
SELECT name AS member, age FROM table_name;
```
이는 `table_name`에서 `name`, `age` 열을 조회하되 `name` 열은 `member`라는 이름으로 표시한다는 의미이다.

#### 실행 순서
`FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY`

### TRIM
문자열의 양 끝단에서 공백 또는 지정된 문자열을 제거하고 반환한다.
```
TRIM({LEADING, TRAILING, BOTH} {제거할 문자열} FROM {다루는 문자열})
```
기본 형태는 위와 같다. 맨 처음에 `LEADING`, `TRAILING`, `BOTH` 옵션 중의 하나를 선택해서 사용하면 되는데 `LEADING`은 문자열의 왼쪽 끝, `TRAILING`은 문자열의 오른쪽 끝, `BOTH`는 문자열의 양쪽 끝에서 제거한다는 의미이다. 아무것도 입력하지 않을 경우 default는 `BOTH`이다. 
제거할 문자열은 제거하고 싶은 문자열을 의미하는데 이것도 아무것도 입력하지 않은 default 값은 공백이다. 

```
SELECT TRIM("  Hello World!   ");
```
위와 같은 예시에서는 양 끝의 공백을 제거한 `Hello World!`가 반환된다.

```
SELECT TRIM(LEADING '가' FROM '가나다라');
```
위의 예시에서는 `가나다라`에서 `가`가 제거된 `나다라`가 반환된다.

#### LTRIM & RTRIM
위의 TRIM 기본 형태에서 `{LEADING, TRAILING, BOTH}` 옵션을 이용해 제거할 문자열의 위치를 지정했는데, 이렇듯 번거롭게 옵션을 지정하지 않고 `LTRIM`, `RTRIM` 함수를 이용해도 된다. `LTRIM`, `RTRIM`은 각각 왼쪽 끝 문자열 제거, 오른쪽 끝 문자열 제거를 의미한다.

`LTRIM` = `TRIM(LEADING)`
`RTRIM` = `TRIM(TRAILING)`

이외에도 문자열 관련해서 `SUBSTR`, `REPLACE`, `LENGTH`, `UPPER`, `LOWER` 함수를 공부해 두도록 하자.

### NVL
`NULL` 값을 다른 값으로 대체할 때 사용하는 함수이다.
```
NVL(column1, replacement)
```
위 명령어를 사용하면 `column1` 열에서 `NULL`값을 찾아 `replacement`로 대체하여 반환한다.
예를 들어 `tbl` 테이블에 `name`이라는 열이 아래와 같이 있을 때

|name|age|
|:--:|:--:|
|Adam|25|
|John|34|
|NULL|13|
|Catherine|42|
```
SELECT NVL(name, 'Unknown') AS name, age FROM tbl;
```
위와 같이 NVL 명령어를 이용하면 `NULL` 값이 `Unknown`으로 대체되어 반환된 것을 알 수 있다. 

|name|age|
|:--:|:--:|
|Adam|25|
|John|34|
|Unknown|13|
|Catherine|42|

\* `NVL`은 oracle 문법이고 SQL Server에서는 `ISNULL`을 사용한다.

<br>

### NULLIF
`NULLIF`는 `NVL`과 반대로 특정 값을 `NULL` 값으로 대체하는 명령어이다. 

```
NULLIF(column1, expression)
```
`column1`에서 `expression`이라는 값을 가지면 `NULL` 값으로 변환하여 반환한다.

```
SELECT name, NULLIF(age, 99) FROM tbl;
```
위 명령어를 이용하면 tbl에서 age 열에 있던 99라는 숫자가 NULL값으로 변환되어 반환된다.

<br>

### COALESCE
```
COALESCE(col1, col2, col3, ...)
```
`col1`, `col2`, `col3`, ...을 순서대로 읽어서 `NULL`이 아닌 첫 번째 값을 반환하는 함수이다. 

아래와 같은 예시를 보자.

|No|Hourly_wage|Salary|Commission|
|:--:|:--:|:--:|:--:|
|1001|10|Null|Null|
|1002|Null|10000|Null|
|1003|Null|Null|1500|

Null 값들이 테이블에 있는 상황에서
```
SELECT No, COALESCE(Hourly_wage, Salary, Commission) AS Total_salary FROM tbl;
```
위의 명령어를 사용하면, 각 열을 순서대로 읽으면서 Null이 아닌 첫 번째 값을 반환하기 때문에 아래와 같은 테이블을 결과로 반환한다.

|No|Total_salary|
|:--:|:--:|
|1001|10|
|1002|10000|
|1003|1500|

### JOIN
두 테이블을 하나로 병합하는 연산이다.

#### INNER JOIN
```
SELECT A1.column1, A2.column2 FROM tbl1 A1 INNER JOIN tbl2 A2 ON A1.column1 = A2.column1;
```
교집합의 개념으로 기준이 되는 key에 따른 column 값이 존재하는 것만 병합하는 것이다.

아래와 같이 A1, A2 테이블이 있다고 하자.

|actor_no|name|gender|guarantee|
|:--:|:--:|:--:|:--:|
|1235|Tom|male|150|
|2067|Mia|female|120|
|3398|Sebastian|male|170|

<br>

|actor_no|movie_no|guarantee|
|:--:|:--:|:--:|
|1235|1001|150|
|3398|1002|120|
|5434|1002|980|

`tbl1`과 `tbl2` 테이블을 actor_no 기준으로 병합하고 싶을 때, 아래와 같은 명령어를 이용하면 된다.
```
SELECT A1.actor_no act_1, A2.actor_no act_2, A2.movie_no, A1.name, A1.gender, FROM tbl1 A1 INNER JOIN tbl2 A2 ON A1.actor_no = A2.actor_no
```

|act_1|act_2|movie_no|name|gender|
|--|--|--|--|--|
|1235|1235|1001|Tom|male|
|3398|3398|1002|Mia|female|

#### OUTER JOIN
```
SELECT A1.column1, A2.column2 FROM tbl1 A1 {LEFT, RIGHT, FULL} OUTER JOIN tbl2 A2 ON A1.column1 = A2.column1;
```
합집합의 개념으로, 기준이 되는 key에 따른 column 값이 존재하지 않더라도 모든 테이블을 병합하는 것이다. OUTER JOIN의 경우 어느 테이블을 기준으로 병합할지 옵션을 정해야 하는데 `LEFT`, `RIGHT`, `FULL` 중 하나를 선택하면 된다. `LEFT`는 왼쪽 (첫 번째 테이블 `tbl1`), `RIGHT`는 오른쪽 (두 번째 테이블 `tbl2`)을 기준으로 병합하고, `FULL`은 왼쪽과 오른쪽 테이블의 모든 행을 포함하여 병합한다.

위의 `tbl1`, `tbl2` 예시로 OUTER JOIN을 해보면,
```
SELECT A1.actor_no act_1, A2.actor_name act_2, A2.movie_no, A1.name, A1.gender FROM tbl1 A1 LEFT OUTER JOIN tbl2 A2 ON A1.actor_no = A2.actor_no;
```

|act_1|act_2|movie_no|name|gender|
|:--:|:--:|:--:|:--:|:--:|
|1235|1235|1001|Tom|male|
|2067|`NULL`|`NULL`|Mia|female|
|3398|3398|1002|Sebastian|male|

위와 같이 column 값이 없을 때도 `NULL` 값으로 대체되며 테이블이 병합되는 것을 볼 수 있다. 이 경우 `LEFT` (`tbl1`)를 기준으로 병합한 것을 알 수 있다.  

#### NATURAL JOIN
```
SELECT * FROM tbl1 NATURAL JOIN tbl2;
```
병합하는 두 테이블에서 같은 이름의 column이 같은 값을 가지는 행만 병합하는 연산이다.

위의 `tbl1`, `tbl2` 예시로 NATURAL JOIN을 해보면,

|actor_no|guarantee|name|gender|movie_no|
|:--:|:--:|:--:|:--:|:--:|
|1235|150|Tom|male|1001|

위와 같이 `actor_no`=1235인 행만 남게 된다. 이는 `tbl1`과 `tbl2`를 비교했을 때 `actor_no`와 `guarantee`라는 두 열이 공통적으로 있는데, 겹치는 두 행 중 `actor_no`=1235는 `tbl1`과 `tbl2`에서 `actor_no`와 `guarantee` 값이 동일하지만 `actor_no`=3398은 `guarantee` 값이 다르기 때문이다. (`tbl1`에서는 170, `tbl2`에서는 120) 

#### CROSS JOIN
CROSS JOIN은 왼쪽 테이블의 각 행에 대한 오른쪽 테이블의 모든 행의 대응을 조합하여 결과를 출력하는 것이다. 따라서 왼쪽 테이블이 M행이고 오른쪽 테이블이 N행이라면 CROSS JOIN을 했을 때 총 M $\times$ N행이 된다.

$$
\begin{bmatrix}A\\B\\ \end{bmatrix}

\begin{bmatrix}X\\Y\\Z\\ \end{bmatrix}
$$

결과 : $(A, X), (A, Y), (A, Z), (B, X), (B, Y), (B, Z)$

코드로는 다음과 같이 작성한다.
```
SELECT * FROM tbl1 CROSS JOIN tbl2;
```
혹은 아래와 같이 더 간단히 쓸 수도 있다.
```
SELECT * FROM tbl1, tbl2;
```

### INSERT
```
INSERT INTO tbl (col1, col2, col5, col7) VALUES (val1, val2, val6, val7);
```

### UPDATE
```
UPDATE tbl SET col1 = val1, col2 = val2, ...
```
or 
```
UPDATE tbl SET (col1, col2, ...) = (val1, val2, ...)
```

### MERGE
```
MERGE INTO tbl1 AS TARGET
USING tbl2 AS SOURCE
ON (연결 조건)
WHEN MATCHED THEN
  UPDATE
  SET 수정 내용
  DELETE (조건)
WHEN NOT MATCHED THEN
  INSERT (col1, col2, ...)
  VALUES (val1, val2, ...);
```

### ALTER
`ALTER TABLE tbl {ADD, MODIFY, RENAME, DROP, ...}`
단, column의 순서를 변경하는 것은 불가능하기 때문에 테이블을 재생성해야 한다.
